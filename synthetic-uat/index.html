01 / AI EVALUATION · IN PROGRESS

Synthetic UAT

Comparing where AI agents and people encounter friction in the same cloud billing task.

01 / OVERVIEW

A shared task for human and AI usability testing.

I designed a cloud billing test platform and scoped a study comparing real participants with survey-informed synthetic personas.

This contract project at Google examines whether AI agents can provide a useful early usability signal. I led the study, designed the proof of concept, ran human sessions, and interviewed UX experts.

02 / PROBLEM / USER CHALLENGE

Finishing a task does not mean getting it right.

A saved budget can cover the wrong costs or notify the wrong person. Completion alone hides these mistakes, while recruiting human testers takes time and resources.

Research decision

Compare final configuration accuracy and friction by setting—not screen count. Survey data informs the personas; human sessions and expert interviews provide a reference for evaluating agent behavior.

The research question is whether agents encounter the same friction as people. Agreement has not yet been established.

03 / SOLUTION

1 workflow, 2 interfaces, 1 evaluator.

Scope the comparison

I limited the proof of concept to one persona and one billing workflow so differences remain interpretable.

Test a deliberate trade-off

The advanced form keeps settings visible; the guided flow reduces simultaneous choices but adds navigation. Both save the same configuration and use a shared evaluator.

SAME TASK · FICTIONAL BILLING ACCOUNT

Set a $1,000 monthly budget for Atlas. Alert only its project owner when actual spend exceeds 80%.

A / DENSE CONFIGURATION

See the settings together.

Scope Atlas project
Budget $1,000 / month
Threshold 80% · actual
Recipient Atlas project owner

A compact form supports fast scanning for experienced users. Users must notice how scope affects recipient eligibility and interpret role-based options.

B / GUIDED QUESTIONS

Decide one step at a time.

01 Which costs should this budget cover?
02 How much can Atlas spend?
03 When should the alert trigger?
04 Who should receive the alert?

A sequence of questions reduces what’s visible at once. It introduces extra navigation and makes the review step important for catching dependencies.

Illustrative walkthrough on a fictional account. Both prototypes save the same budget configuration.

Inspect the path

Session logs distinguish incorrect decisions from timeouts or action failures. The console supports event review, re-scoring, and export.

04 / IMPACT / OUTCOME

A testable platform; comparative results pending.

  • Research: persona survey, human UAT sessions, and UX expert interviews.
  • Deliverables: study design, test platform, proof-of-concept interfaces, and evaluation workflow.
  • Status: the study is in progress; no comparative outcomes are reported.

05 / OPPORTUNITIES / TARGET USERS

An early signal for teams, with human follow-up.

The opportunity is to help UX and product teams identify candidate issues before deeper human testing.

If both groups miss the same dependency, investigate the interface explanation. If only agents miss it, inspect their perception and action traces before generalizing to people. These are next-step criteria, not findings.

06 / REFLECTION

Measure where synthetic users stop being useful.

Narrow scope improves interpretability but limits generalization. The two flows also change hierarchy, wording, and navigation together.

Next, measure agreement by setting, weigh accuracy against time, and isolate individual design changes in a follow-up study. Agent feedback should complement human evidence.
